# Deploy SaidHere on Render

SaidHere uses a Render Node web service plus Render Postgres. The root `render.yaml` defines both resources as a Blueprint.

## One-click architecture

- Web service: `saidhere-api-9ab3`
- Database: `saidhere-db-9ab3`
- Region: Singapore
- Database public access: disabled (`ipAllowList: []`)
- API health check: `/health`
- API admin key: generated by Render as `ADMIN_KEY`
- Browser admin username: `ADMIN_USERNAME` (defaults to `admin`)
- Browser admin password: `ADMIN_PASSWORD`
- Browser admin session signing key: `ADMIN_SESSION_SECRET`

The API receives the database's private Render connection string through `DATABASE_URL` automatically.

## Deploy

1. In Render, choose **New > Blueprint**.
2. Connect the GitHub repository `9AB3/SaidHere`.
3. Render detects the root `render.yaml`.
4. Review the resources and apply the Blueprint.
5. Set a strong `ADMIN_PASSWORD` when Render asks for the unsynchronised environment value.
6. Wait for the database and web service to finish deploying.
7. Open `https://saidhere-api-9ab3.onrender.com/health`.

Expected response:

```json
{"ok":true,"service":"saidhere-api"}
```

The web service starts with:

```text
npm run migrate && npm start
```

so the Postgres tables are created automatically on deployment.

## Browser admin portal

Open:

```text
https://saidhere-api-9ab3.onrender.com/admin
```

The portal provides a normal username/password login and lets you:

- create Walls and receive the one-time NFC URL;
- edit Wall names and locations;
- deactivate or reactivate Walls;
- replace an NFC plaque URL while preserving Wall history;
- clear all messages from a Wall;
- permanently delete a Wall;
- log out of the admin session.

The browser login uses a signed HttpOnly cookie, CSRF protection on actions, rate-limited login attempts and a limited session lifetime.

### Existing deployments

If `ADMIN_PASSWORD` has not been added yet, the browser portal temporarily falls back to:

```text
Username: admin
Password: <the existing ADMIN_KEY value>
```

This keeps an existing Render deployment usable immediately. For normal use, add these environment variables in **Render > saidhere-api-9ab3 > Environment** and redeploy:

```text
ADMIN_USERNAME=<your preferred username>
ADMIN_PASSWORD=<a strong unique password>
ADMIN_SESSION_SECRET=<a long random secret>
```

`ADMIN_SESSION_SECRET` can also remain generated by the Render Blueprint. Once `ADMIN_PASSWORD` is present, the browser portal no longer uses `ADMIN_KEY` as its password.

`ADMIN_KEY` remains separate for programmatic admin API calls such as `POST /api/admin/walls` with `X-Admin-Key: <ADMIN_KEY>`.

## Creating and programming a Wall

1. Log into the admin portal.
2. Enter the Wall name and optional location.
3. Press **Create Wall + NFC URL**.
4. Copy the one-time NFC URL shown on the result page.
5. Program that exact URL onto the physical NFC tag.
6. Test the tag before permanently write-locking it.

The URL looks like:

```text
https://saidhere.app/t/<secret-token>
```

The raw token is returned only when the Wall is created or its NFC URL is replaced. It is never stored in Postgres; only its SHA-256 hash is retained. If the raw URL is lost, use **Replace NFC** in the portal to create a new one while preserving the Wall and its history.

## Flutter API URL

The app defaults to:

```text
https://saidhere-api-9ab3.onrender.com
```

To use a different Render service or a future custom API domain:

```bash
flutter run --dart-define=API_BASE_URL=https://your-api.example.com
```

Codemagic also has `API_BASE_URL` as a workflow variable.

## Custom domain later

Once `saidhere.app` is owned and configured, keep NFC links on `https://saidhere.app/t/<token>` so Apple Universal Links and Android App Links can open the installed app. The backend can remain on the Render subdomain or move behind something like `https://api.saidhere.app`.

## Security notes

- Render Postgres is private-only in the Blueprint.
- Phones never connect directly to Postgres.
- Anonymous app sessions use opaque random bearer tokens stored locally on the device.
- NFC secrets are hashed before storage.
- Browser admin authentication uses a signed HttpOnly cookie and CSRF-protected mutations.
- Login attempts are rate limited.
- The API `ADMIN_KEY`, browser password and session signing secret are not committed to GitHub.
- A valid plaque URL grants 15 minutes of server-enforced write access to that Wall.
- Six posts per minute per anonymous session are allowed before the server temporarily blocks more.
- Three distinct reports automatically hide a message.

A normal static NFC tag can still have its URL copied and replayed. Permanent write-locking stops rewriting, not cloning. For production-grade proof of a genuine physical tap, use a cryptographic NFC tag such as NTAG 424 DNA and verify its dynamic authentication server-side.

For a larger public rollout, add automated text moderation, a moderator console and stronger anti-bot controls.
