# SaidHere

**Real places. Real people. Anonymous thoughts.**

SaidHere is a location-bound anonymous message app. A physical NFC plaque identifies a specific Wall. Tapping the plaque discovers that Wall and unlocks writing for 15 minutes. After that, the Wall remains readable from the user's discovered-Walls list, but writing requires another physical tap.

## What is already implemented

- Flutter app for iOS, Android and web
- NFC/deep-link route: `/t/<secret-tag-token>`
- Public Wall route: `/w/<wall-slug>`
- Anonymous Supabase authentication — no sign-up UI
- Per-Wall discovery history
- 15-minute write/reply window after a plaque tap
- Text-only anonymous posts, max 300 characters
- One-level replies
- Dates only; no username, avatar, likes or followers
- Previous-year browsing on long-lived Walls
- Reporting flow
- Automatic temporary hiding after three distinct reports
- Private author IDs retained only in the database for abuse controls
- NFC tag token stored separately from the public Wall record
- Admin SQL helper to provision new physical plaques
- Codemagic build workflow
- GitHub analyze/test workflow
- iOS Universal Link / Android App Link bootstrap templates

## Product rules baked into the code

SaidHere deliberately does **not** have profiles, handles, likes, DMs, follower counts, global feeds or searchable public Walls. The place is the network.

A user can revisit a Wall they previously found and read it, but writing is locked unless there is a non-expired physical visit generated by a plaque tap.

## Stack

- Flutter / Dart
- Supabase Auth + Postgres
- `go_router` for web/native deep links
- `shared_preferences` for lightweight device history

Current dependency versions were selected against the stable package releases available in October 2026.

## 1. Generate native platform folders

The repository keeps generated Flutter platform boilerplate out of source control so the current Flutter stable templates are used.

```bash
python3 tool/bootstrap_platforms.py --host saidhere.app
flutter pub get
```

The script runs `flutter create` if needed, then adds SaidHere's Android/iOS deep-link configuration.

## 2. Configure Supabase

Follow [SUPABASE_SETUP.md](SUPABASE_SETUP.md).

At minimum:

1. Create a Supabase project.
2. Enable **Anonymous Sign-Ins**.
3. Run `supabase/migrations/001_initial.sql`.
4. Copy your project URL and public anon/publishable key.

## 3. Run

```bash
flutter run \
  --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=YOUR_PUBLIC_KEY \
  --dart-define=APP_HOST=saidhere.app
```

For local/demo testing, apply `supabase/seed.sql` and add:

```text
--dart-define=DEMO_TAG_TOKEN=demo-newcastle-wall-2026
```

The home screen will then expose an **Open demo Wall** button.

## 4. Create your first real Wall

Run `supabase/NEW_WALL.sql` in the Supabase SQL editor.

It returns a URL similar to:

```text
https://saidhere.app/t/4ca8...<random secret>...31af
```

Encode that exact URL onto the NFC tag, test it, then permanently write-lock the tag.

See [DOMAIN_LINKS.md](DOMAIN_LINKS.md) for Universal Link / App Link deployment.

## Database privacy model

The browser/app never receives the post `author_id`. Public post reads go through `visible_wall_posts`, which intentionally exposes only post ID, Wall ID, parent ID, body, date and reply count.

The anonymous user ID remains server-side so repeated abuse can later be rate-limited or banned without adding visible identities to SaidHere.

The secret NFC tag token is stored in `wall_tags`, not `walls`, so discovering a Wall does not reveal the secret required to start a fresh writing session.

## Physical plaque recommendation

A simple production plaque can read:

```text
SAIDHERE

(( NFC ))
TAP HERE

Leave something behind.
```

Put the locked NFC in a non-metallic window/layer inside the plaque. If the face itself is metal, use an on-metal NFC tag or isolate the antenna from the metal with a ferrite layer.

## Before a public launch

The MVP is complete enough to test with real plaques, but a large public rollout should also add CAPTCHA on anonymous account creation, backend rate limiting beyond the built-in posting limits, automated text moderation, a moderator/admin review dashboard, legal pages, production signing/store metadata and real Apple/Android domain-association credentials.

## Suggested first field test

Create 2–3 Walls, install them in controlled locations, and seed each with 5–10 messages. Test cold/warm NFC taps on iPhone and Android, replies, 15-minute expiry, revisiting from **Walls you've found**, reporting and physical read range through the final plaque material.
